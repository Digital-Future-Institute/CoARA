The technical approach to opening data is based on the **[five-star data deployment scheme](http://5stardata.info/)** defined by Tim Berners-Lee .

This scheme proposes an incremental scale of data openness levels, where each level represents progress toward the core objectives of open data: **freedom of use, reuse, and redistribution**.

![Five-star data opening scheme](https://5stardata.info/images/5-star-steps.png)

*Source: Five-star data opening scheme Tim Berners-Lee (2012)*

## Examples for Each Level of Tim Berners-Lee 5-Star Open Data Plan

Example dataset used throughout:  
**The temperature forecast for Galway, Ireland for the next 3 days.**

### 1 Star  
**Make your data available on the Web (in any format) under an open licence.**

**Example:**  
A PDF document published on a website showing a table:

| Date | Forecast Temperature |
|------|----------------------|
| Day 1 | 12┬░C |
| Day 2 | 14┬░C |
| Day 3 | 11┬░C |

The file is downloadable and openly licensed, but the data is not easily reusable.

### 2 Stars  
**Make it available as structured data (e.g., Excel instead of a scanned image).**

**Example:**  
An Excel (.xlsx) file containing:

| Date       | Temperature (┬░C) |
|------------|------------------|
| 2025-03-01 | 12 |
| 2025-03-02 | 14 |
| 2025-03-03 | 11 |

The data is structured and machine-readable, but the format is proprietary.

### 3 Stars  
**Make it available in a non-proprietary open format (e.g., CSV instead of Excel).**

**Example:**  
A CSV file (`forecast.csv`):

```csv
date,temperature_c,location
2025-03-01,12,Galway
2025-03-02,14,Galway
2025-03-03,11,Galway
```

### 4 Stars  
**Use URIs to denote things, so that people can point to your data.**

**Example (RDF/Turtle format):**

```turtle
@prefix ex: <http://example.org/weather/> .
@prefix schema: <http://schema.org/> .

ex:forecast2025-03-01
    schema:date "2025-03-01" ;
    schema:location <http://dbpedia.org/resource/Galway> ;
    schema:temperature "12" .
```

Each entity (forecast, location, date) has a unique URI, making it identifiable and referenceable.

### 5 Stars  
**Link your data to other datasets to provide context.**

**Example (Linked Data):**

```turtle
@prefix ex: <http://example.org/weather/> .
@prefix owl: <http://www.w3.org/2002/07/owl#> .

ex:Galway
    owl:sameAs <http://dbpedia.org/resource/Galway> .
```

Here, the dataset links **Galway** to an external dataset (e.g., DBpedia), enabling richer queries and contextual integration with other open datasets.

## The Great Leap to the Third Star

Achieving the **third star** means that data is published in a **non-proprietary format**, enabling anyone to consume and reuse it.

To support this, open data organisations promote the standardisation of open formats to facilitate reuse and interoperability.

## Common Open Formats

| Format | Description | Proposed Standard / Scheme |
|---------|-------------|----------------------------|
| **CSV** | Tabular data format where columns are delimited by commas (other separators such as semicolons are also used). | Good practices (e.g., RFC 4180). JSON Table Schema can complement CSV. |
| **JSON** | Data exchange format based on key value pairs, inspired by the JavaScript object model. Supports nested structures. | JSON Schema |

## Data Types and Recommended Formats

Depending on the type of data being published, different formats are recommended.

### Generic Data
Data without specialised applications, typically from databases, spreadsheets, or information tables.

**Recommendations:**
- Use standard, open (non-proprietary) formats whenever possible.
- Proprietary formats may be used in justified cases (e.g., historical data, costly transformations).
- Prefer **CSV** and **JSON** for database and spreadsheet data.

### Images
Photographic or visual data.

**Recommended formats:**
- **JPEG**
- **PNG**
- **SVG** (scalable vector graphics for web rendering)

### Statistical Data
Data used primarily by specialised statistical users.

**Recommended formats:**
- **SDMX** (Statistical Data and Metadata Exchange OECD standard)
- **SPSS (PSPP)**
- **STATA**
- Additionally, publish a **CSV version** to ensure broader accessibility.

### Georeferenced Data
Geographic data used to capture, store, manipulate, analyse, and display spatial information.

**Common formats:**
- `.kml`
- `.geojson`
- `.topojson`

## Designing an Open Data Policy

When designing an open data policy, it is essential to:

- Focus on users and consult data demand.
- Prioritise datasets based on community value and relevance.
- Identify **high-value datasets** that promote public participation and accountability.
- Consider urgency and public interest factors.

In situations of national or international contingency such as natural disasters, epidemics, emergencies, or corruption cases data should be prioritised for rapid publication.

A user-centred, value-driven approach ensures that open data policies maximise transparency, participation, and societal impact.
